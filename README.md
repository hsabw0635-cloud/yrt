# نظام إدارة حضور الطلاب الجامعي

تطبيق ويب متكامل (RTL / عربي) لإدارة الحضور الجامعي، مبني على:

- **الواجهة:** React + Vite + TypeScript
- **الخلفية:** Node.js + Express
- **قاعدة البيانات:** MySQL 8
- **التحديث اللحظي:** Server-Sent Events (SSE)
- **التحقق من الحضور:** صورة فورية من الكاميرا + مقارنة بصرية بمكان صور زملاء المحاضرة
- **التقارير:** Excel (XLSX) و PDF بالعربية

> لا يحتوي التطبيق على بيانات وهمية. يتم إنشاء حساب المدير الأولي من متغيرات البيئة، ثم يقوم المدير بإنشاء بقية البيانات من الواجهة.

---

## 1. المتطلبات

- Node.js 20 أو أحدث (يُفضّل 22 LTS)
- MySQL 8.x يعمل محلياً، أو Docker / Docker Compose

## 2. الإعداد المحلي

### أ) تثبيت الحزم

```bash
npm install
```

### ب) إنشاء ملف الإعدادات

```bash
copy .env.example .env
```

ثم عدّل `.env` وخصوصاً:

```env
JWT_SECRET=قيمة-عشوائية-طويلة- جداً
# رابط Realtime Database يُنسخ من كونسول Firebase ← Realtime Database ← Data
FIREBASE_DATABASE_URL=https://yar1-336c6-default-rtdb.firebaseio.com
FIREBASE_ROOT=campusAttendance
ADMIN_USERNAME=admin
ADMIN_PASSWORD=كلمة-مرور-قوية-8-أحرف-على-الأقل
ADMIN_FULL_NAME=مدير النظام
```

> يجب إنشاء Realtime Database في مشروع Firebase والسماح بالقراءة/الكتابة مؤقتاً في قواعد الأمان، وإلا سيعمل التطبيق محلياً فقط ولن تُحفظ البيانات في Firebase. يعيد السيرفر المحاولة كل دقيقة.

### ج) تجهيز قاعدة البيانات وحساب المدير

```bash
npm run setup
```

### د) تحميل خط PDF العربي

```bash
npm run download:font
```

### هـ) التشغيل

```bash
npm run dev
```

- الواجهة: `http://localhost:5173`
- API: `http://localhost:4000`

سجّل الدخول بحساب المدير الذي ضبطته في `.env`.

## 3. التشغيل عبر Docker

```bash
copy .env.example .env
# عدّل المتغيرات المطلوبة في .env

docker compose exec app npm run migrate

docker compose exec app npm run download:font
```

ثم افتح `http://localhost:4000`.

## 4. ترتيب الاستخدام داخل التطبيق

1. المدير: يضيف الأقسام والمراحل ويربطها ببعضها.
2. المدير: ينشئ حسابات الدكاترة والطلاب، ويضيف المواد، ثم جدول المحاضرات (اليوم، الوقت، القاعة، الدكتور).
3. الطالب: يسجل الدخول أول مرة ويكمل ملفه (الاسم الرباعي، القسم، المرحلة، نوع الدراسة، الرقم الجامعي، صورة اختيارية).
4. الدكتور: يفتح محاضرته بالزر «فتح تسجيل الحضور». تظهر الحالة مباشرة عند الطلاب المرتبطين.
5. الطالب: يضغط «تسجيل الحضور»، يسمح بالكاميرا، يلتقط صورة فورية داخل القاعة، ثم يؤكد. تتم مقارنة مكان الصورة بصور زملاء الجلسة، وأي اختلاف يظهر للدكتور باللون الأحمر.
6. الدكتور: يتابع قائمة الحاضرين وتحديثات الإحصاء مباشرة، ويمكنه إغلاق التسجيل.
7. المدير والدكتور: يستخرجان التقارير من صفحة التقارير.

## 5. ملاحظات أمنية مهمة

- كلمات المرور مشفّرة بـ bcrypt ولا تُخزّن كنص صريح.
- الجلسة عبارة عن JWT داخل cookie من نوع HttpOnly.
- لكل دور صلاحيات منفصلة:
  - المدير: إدارة كاملة.
  - الدكتور: محاضراته وطلابه فقط.
  - الطالب: ملفه وحضوره فقط، ولا يستطيع تعديل سجل الحضور.
- منع تكرار الحضور لنفس الطالب في نفس الجلسة عبر قيد فريد في قاعدة البيانات.
- وقت الحضور يُسجَّل من السيرفر (`NOW()`) وليس من المتصفح.
- الصور تُحفظ خارج قاعدة البيانات في مجلد `storage` وتُقدَّم فقط عبر route محمي بالصلاحيات.
- يتم تسجيل العمليات المهمة في جدول `audit_logs`.
- الكاميرا تعمل فقط في سياق آمن: `localhost` أو HTTPS. عند النشر استخدم HTTPS.

## 6. بنية المشروع

```text
server/
  db/          مخطط قاعدة البيانات وترحيلها وإنشاء المدير
  routes/      مسارات API حسب الدور
  reports.mjs  بناء التقارير وتصدير Excel/PDF
  sessions.mjs إدارة جلسات المحاضرات وحساب الحالات
  uploads.mjs  حفظ الصور وحماية المرفقات
web/
  src/pages/   صفحات المدير والدكتور والطالب
  src/components/ مكوّنات الواجهة المشتركة
dist/          نتيجة بناء الواجهة
storage/       الصور المحفوظة (غير مضمّنة في Git)
```

### التحقق الذكي من الصور (Gemini Vision)
أضف في `.env`:

```env
GEMINI_API_KEY=مفتاح-Google-AI-Studio
GEMINI_MODEL=gemini-2.0-flash
AI_MIN_SCORE=0.55
```

عند وجود المفتاح تُقارَن صورة كل طالب بصور كل زملائه في الجلسة عبر Gemini، مع تجاهل الوجه والملابس والتركيز على مكان المحاضرة. أي طالب لا يتطابق مكانه يظهر باللون الأحمر عند الدكتور. عند غياب المفتاح أو فشل الاتصال يعمل الفحص البصري المحلي تلقائياً.

### تنظيف الصور
تُحذف صور الحضور فقط تلقائياً **بعد 5 ساعات من تسجيل الحضور** (مع تدارك الصور القديمة عند تشغيل السيرفر)، ويبقى سجل الحضور ودرجة المطابقة وحالة المخالفة محفوظة. يمكن للمدير تشغيل التنظيف اليدوي من زر «تنظيف صور الحضور» في لوحة التحكم.

### حذف الحضور يدوياً
يمكن حذف أي سجل حضور (مع صورته) من زر «حذف» في التقارير وسجلات الحضور عند المدير، أو من زر «حذف الحضور» لكل طالب في صفحة جلسة المحاضرة عند الدكتور. الحذف نهائي ويُسجّل في سجل التدقيق.
